# S4. Lifecycle Stress Tests and Ablation Analysis

## S4.1 Targeted stress tests of the full model

In the lifecycle stress tests, each condition targets a specific authorization failure or the preservation of an action that retains independent support. For actions with surviving valid support, the preservation rate gives the proportion that retain access. Higher values indicate greater preservation. For the other conditions, a lower violation rate indicates that fewer eligible trials ended in the specified violation. For each condition, the table gives the trial count, the metric, and the measured value for the full model as follows.

| Targeted condition | Trials | Metric | Full model |
|---|---:|---:|---:|
| Stale or false persistent authorization memory | 60,000 | ACVR | 0 |
| Checkpoint restoration after invalidation | 30,000 | ARR | 0 |
| Surviving independent authorization support | 80,000 | IPR | 1.000000 |
| Concurrent bounded authority use | 120,000 | CRR | 0 |
| Exact-support substitution | 50,000 | SSVR | 0 |
| Authorization change before protected commit | 80,000 | SACR | 0 |

## S4.2 Metric definitions

For the lifecycle conditions in the above table, each rate counts an outcome among the cases eligible for that outcome. For the Authorization Consistency Violation Rate (ACVR), eligible cases are protected commit attempts that lack current authorization immediately before commit. For the Independent Path Preservation Rate (IPR), a case is eligible if at least one valid support survives. The Authority Resurrection Rate (ARR) counts instances in which authority invalidated before checkpoint restoration becomes executable after restoration. For trials involving bounded concurrency, exact-support substitution, or an authorization change before commit, the corresponding metrics are the Concurrency Reuse Rate (CRR), Silent Support Substitution Violation Rate (SSVR), and Stale Authorization Commit Rate (SACR), respectively. The definitions specify the event and denominator for each rate as follows.

$$
\mathrm{ACVR}=
\frac{N_{\text{protected commits with }AC(a,t_c^-)=0}}
{N_{\text{protected commit attempts with }AC(a,t_c^-)=0}}.
$$

$$
\mathrm{IPR}=
\frac{N_{\text{authorized actions preserved through surviving supports}}}
{N_{\text{cases with at least one surviving valid support}}}.
$$

$$
\mathrm{ARR}=
\frac{N_{\text{cases where invalid authority becomes executable after restoration}}}
{N_{\text{restore cases invalidated before restoration}}}.
$$

$$
\mathrm{CRR}=
\frac{N_{\text{concurrency trials with unauthorized bounded reuse}}}
{N_{\text{bounded concurrency trials}}}.
$$

$$
\mathrm{SSVR}=
\frac{N_{\text{executions with silent support substitution}}}
{N_{\text{targeted support substitution trials}}}.
$$

$$
\mathrm{SACR}=
\frac{N_{\text{stale authorization commits}}}
{N_{\text{precommit authorization change trials}}}.
$$

## S4.3 Component-targeted ablations

To assess the contribution of each component, the targeted trials compare two configurations, namely, the full model and the model with that component removed. In the protected-commit ablation, the pre-dispatch gap is 5–500 ms and the authorization-change hazard is 0.85/s. Only the risk-layer ablation measures treatment. For this ablation, the Risk Treatment Rate (RTR) and Friction Introduction Rate (FIR) describe treatment among authorized actions. For each component, the table gives the number of targeted trials and the measured rates in both configurations as follows.

| Removed component | Targeted trials | Metric | Full model | Ablated |
|---|---:|---:|---:|---:|
| Memory revalidation | 60,000 | ACVR | 0 | 1.000000 |
| Memory revalidation under restore | 30,000 | ARR | 0 | 1.000000 |
| Independent-support tracking | 80,000 | IPR | 1.000000 | 0.320975 |
| Atomic reservation | 120,000 | CRR | 0 | 0.632750 |
| Exact-support revalidation | 50,000 | SSVR | 0 | 1.000000 |
| Protected commit boundary | 80,000 | SACR | 0 | 0.188488 |
| AI risk layer | 90,000 | RTR / FIR | 0.607302 / ≈0.2581 | 0 / 0 |

## S4.4 Interpretation

As shown in the ablation table, the effect of removing an enforcement component depends on which authorization condition the test exercises. Memory revalidation prevents the reuse of stale authorization from memory. After selective revocation, independent-support tracking preserves actions with surviving valid support. Under concurrent use, atomic reservation protects bounded authority. At protected commit, exact-support revalidation prevents silent substitution and the protected commit boundary prevents execution when a late trusted-state change invalidates planning-time authorization. Thus, removing an enforcement component can change which actions execute, whereas removing the risk layer changes treatment only among actions that already hold authorization.
