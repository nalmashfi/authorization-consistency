# S3. Formal and Controlled Authorization-Consistency Experiments

## S3.1 Formal implementation validation

To test the runtime authorization resolver against the formal decision oracle, the experiment uses synthetic authorization histories generated from the mathematical model. For each history, the oracle and the resolver independently decide whether the requested action has current authorization. It can be observed that both decisions agree across the generated histories. However, the experiment provides no comparison of the two decisions for graphs outside the generated case set. For the generated histories, the definition of the Formal Decision Error Rate (FDER) and the observed value are as follows.

$$
\mathrm{FDER}
=\frac{N_{\text{formal decision mismatches}}}{N_{\text{formal test cases}}}.
$$

$$
\mathrm{FDER}=0/60{,}000=0.
$$

## S3.2 Controlled comparison configurations

In the controlled experiment, four enforcement configurations govern access to protected commit across the same 180,000-case corpus. For attempts without current authorization, the Authorization Consistency Violation Rate (ACVR) gives the proportion that reach protected commit under each configuration. For the proposed model, the experiment also records how many of the 60,000 legitimately authorized actions reach protected execution. In fact, the proposed model preserves every such action. For the above corpus, the enforcement rule and ACVR for each configuration and the preservation count for the proposed model are as follows.

| Configuration | Authorization behavior | ACVR |
|---|---|---:|
| No Gate | no protected authorization enforcement | 1.0000 |
| Planning Snapshot | authorization checked during planning only | 0.6667 |
| Memory Only | persistent/remembered authorization used without current trusted resolution | 0.8333 |
| Proposed Model | current support resolution + protected enforcement | 0 |

For each of the four enforcement configurations, the table gives the ACVR measured on the controlled corpus. However, a reported rate alone leaves its denominator undetermined. ## S3.3 Controlled scenario dimensions

In the controlled corpus, the scenario dimensions fall into three groups, namely, current authority, memory and support, and restoration and timing. A single scenario can combine dimensions from these groups. Within the timing group, an authorization change after planning and an authorization change near protected commit describe different cases. For each of the above groups, the table lists the dimensions used to construct the controlled scenarios as follows.

| Aspect | Scenario dimensions |
|---|---|
| Current authority | Current valid authorization, revoked authorization, expired authorization, exhausted or occupied bounded authority |
| Memory and support | Persistent stale or false memory, independent valid supports |
| Restoration and timing | Checkpoint restoration, authorization change after planning, authorization change near protected commit |

## S3.4 Interpretation

For the controlled experiment, rejection of unauthorized actions and preservation of access for legitimately authorized actions answer different questions about enforcement. A rule that denies every action can reduce unauthorized execution. However, the same rule prevents legitimately authorized actions from reaching protected commit. Thus, the controlled evaluation uses ACVR together with legitimate-action preservation and the Independent Path Preservation Rate (IPR) to assess access for authorized actions.
