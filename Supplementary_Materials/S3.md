# S3. Formal and Controlled Authorization-Consistency Experiments

## S3.1 Formal implementation validation

For each synthetic history generated from the mathematical model, the formal oracle and the runtime resolver independently decide whether current authority permits the requested action. A disagreement counts as a formal decision mismatch. Across the generated histories, the resolver returned the decision specified by the oracle for every action tested. Thus, the comparison establishes agreement for the histories and graphs tested, while decisions for other graphs remain unverified. For this test set, the definition and observed value of the Formal Decision Error Rate (FDER) are as follows.

$$
\mathrm{FDER}
=\frac{N_{\text{formal decision mismatches}}}{N_{\text{formal test cases}}}.
$$

$$
\mathrm{FDER}=0/60{,}000=0.
$$

## S3.2 Controlled comparison configurations

Across the same corpus of 180,000 cases, the controlled experiment compares four configurations that differ in where and how they enforce authorization. For attempts that lack current authorization, the Authorization Consistency Violation Rate (ACVR) measures the proportion that reach protected commit. The experiment checks legitimate access separately. Under the proposed model, all 60,000 legitimately authorized actions reached protected execution. For the controlled corpus, the enforcement rules, the corresponding values of ACVR, and the count of actions preserved by the proposed model are as follows.

| Configuration | Authorization behavior | ACVR |
|---|---|---:|
| No Gate | no protected authorization enforcement | 1.0000 |
| Planning Snapshot | authorization checked during planning only | 0.6667 |
| Memory Only | persistent/remembered authorization used without current trusted resolution | 0.8333 |
| Proposed Model | current support resolution + protected enforcement | 0 |

### Denominators for the comparison

For a given configuration, the denominator of ACVR counts attempts that lack current authorization immediately before protected commit. The published table gives only the rate. Across different sets of controlled cases, different counts of unauthorized attempts and protected commits can give exactly the same rate for a configuration. Thus, recovering the denominator requires the underlying counts, which are absent from the released records for this experiment.

## S3.3 Controlled scenario dimensions

To construct a controlled scenario, the experiment combines conditions governing the current grant, the evidence retained in memory, and the timing of authorization changes. A scenario can exercise more than one condition. Within the timing group, a change after planning and a change near protected commit test distinct points in the authorization lifecycle. For the three groups, namely, current authority, memory and support, and restoration and timing, the scenario dimensions are as follows.

| Aspect | Scenario dimensions |
|---|---|
| Current authority | Current valid authorization, revoked authorization, expired authorization, exhausted or occupied bounded authority |
| Memory and support | Persistent stale or false memory, independent valid supports |
| Restoration and timing | Checkpoint restoration, authorization change after planning, authorization change near protected commit |

## S3.4 Interpretation

For an attempt that lacks current authorization, ACVR measures whether enforcement still allows the action to reach protected commit. Denying every action can prevent unauthorized commits. However, the same rule denies access to every action that has the support it needs for execution. Thus, the evaluation reports legitimate-action preservation alongside ACVR and uses the Independent Path Preservation Rate (IPR) to assess actions with a surviving valid support.
