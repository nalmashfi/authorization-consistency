# S7. Runtime Measurements and Supporting Files

## S7.1 Measurement environment

For support resolution and protected execution, the runtime evaluation measures latency under the same software environment. The measurements use CPython 3.13.5 on Linux x86-64. In this environment, five central processing units (CPUs) were available for timing individual operations and measuring concurrent execution. For comparisons across configurations, the principal statistic is median latency, with upper percentiles included where the measurements provide them.

## S7.2 Nested support-resolution measurements

For each graph size, the nested measurements pair the latency of support resolution with the complete latency of the same invocation. In the table, the vertex and edge counts identify the graph used for each configuration. As a check on the nested measurements, the final column counts invocations in which complete latency fell below support resolution latency. This count is zero for every graph. For each graph, the table gives both median latencies, followed by the fitted slope per vertex and the coefficient of determination as follows.

## S7.4 Protected-state operations

For protected execution, the latency measurements cover three operations, namely, atomic reservation, protected commit, and atomic reservation followed by protected commit. Each operation has the same repetition count. As shown in the table, the median latency for the combined operation exceeds the median for either operation measured separately in this environment. For the three operations, the repetition counts and the median and upper percentiles of latency are as follows.

| Operation | Repetitions | Median µs | P95 | P99 |
|---|---:|---:|---:|---:|
| Atomic reservation | 30,000 | 0.240 | 0.261 | 0.391 |
| Protected commit | 30,000 | 0.220 | 0.291 | 0.440 |
| Reservation + protected commit | 30,000 | 0.471 | 0.711 | 1.022 |
