# S7. Runtime Measurements and Supporting Files

## S7.1 Measurement environment

The runtime evaluation measures support resolution and protected execution in a common environment, using CPython 3.13.5 on Linux x86-64. At the time of measurement, the process had five central processing units (CPUs) available for individual and concurrent operations. For each configuration, median latency describes the typical invocation. In configurations with upper percentiles, those percentiles describe the slower invocations observed under the same measurement conditions.

## S7.2 Nested support-resolution measurements

For each invocation, nested timing measures support resolution inside the interval used to measure the complete operation on the same graph. The final column counts violations of that nesting relation. Across all graph sizes, no invocation had a complete latency below the latency measured for support resolution within it. For the graphs identified by their vertex and edge counts, the paired medians and the fitted relation between support resolution latency and vertex count are as follows.

| $\lvert V_t\rvert$ | $\lvert\Lambda_t\rvert$ | Repetitions | Support median µs | Complete median µs | Complete < Support violations |

| 1,000 | 996 | 1,800 | 20.581 | 41.853 | 0 |
| 10,000 | 9,987 | 500 | 206.411 | 426.303 | 0 |
| 50,000 | 49,947 | 140 | 1,063.372 | 2,133.155 | 0 |

## S7.4 Protected-state operations

For protected execution, the table compares atomic reservation with protected commit and with the sequence that performs both operations. Each configuration uses the same number of repetitions. In this environment, the combined sequence took longer at the median than either atomic reservation or protected commit measured on its own. For each configuration, the repetition count and the median and upper percentiles of operation latency are as follows.

| Operation | Repetitions | Median µs | P95 | P99 |
|---|---:|---:|---:|---:|
| Atomic reservation | 30,000 | 0.240 | 0.261 | 0.391 |
| Protected commit | 30,000 | 0.220 | 0.291 | 0.440 |
| Reservation + protected commit | 30,000 | 0.471 | 0.711 | 1.022 |

## S7.5 Concurrent execution

At each concurrency level, throughput counts completed operations per second, while latency describes the time taken by an individual operation. Throughput did not rise consistently with concurrency. For configurations with the same median latency, the upper percentiles show differences among the slower operations that the median alone conceals. For comparison across the measured concurrency levels, the operation counts, latency percentiles, and observed throughput are as follows.
